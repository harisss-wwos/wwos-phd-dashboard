2. First login — and change your password right away

  1. Go to the live dashboard and click Login (top-right).
  2. Enter the username and temporary password the Owner gave you.
  3. Your name and role appear in the toolbar.

Change your password immediately after first login

  1. Click your avatar (top-right) to open your Profile page.
  2. Under Security, click Change Password.
  3. Enter your current password, then your new password (minimum 6 characters) twice.
  4. Click Update Password.
Treat the temporary password as one-time. Don't share accounts — everyone should log in as themselves so the data log and help threads attribute actions correctly.

While you're on the Profile page

  • Set a display name and optionally upload a profile photo (avatar). These are visible to other users across the dashboard.
  • Your login ID and role are read-only — only the Owner can change a role.

3. Uploading data (Admin / Manager / Owner)

Data is uploaded as a CSV export of PHD tickets. On upload, the file is merged into the current quarter's dataset and published to everyone automatically (it becomes the live data for all viewers).

How to upload

  1. Log in.
  2. On the live dashboard, click Upload new data (green button, top-right).
  3. Pick your CSV. The dashboard processes it, merges it with existing tickets, and publishes.
  4. An Upload Complete summary shows what changed (added / updated / reopened / auto-closed / unchanged).

What "merge" does

  • New tickets are added.
  • Existing tickets update when status advances (e.g. Assigned → Resolved).
  • Reopened tickets (was Resolved/Closed, now Work In Progress again) are flagged and shown as PURPLE.
  • Missing tickets that were previously Resolved are treated as auto-closed.
  • The whole change set is recorded in the Update data log.

Quarters

The dashboard is organized by quarter (e.g. Q3 2026). The live quarter is the current quarter based on today's date. If your upload contains tickets from a different quarter, the dashboard flags it and asks you to review before overwriting that quarter's data — this prevents accidentally mixing quarters.

4. CSV fields — what the upload needs

Each row is one ticket. The parser keys off column headers, so header names must match. A row is only kept if it has a ShortId (or IssueId, which is treated as the ShortId).

Required / most important

FieldWhy it matters
ShortId (or IssueId)Unique ticket ID. Rows without it are skipped. Used as the merge key.
CreateDateCreation time. Drives ticket age, the 240-hour (10-day) deadline, created charts, and SLA timing.
StatusAssigned, Work In Progress, Pending, Researching, Resolved, Closed. Drives queue counts, color classification, reopen detection.
ResolvedDateWhen resolved. Drives resolved charts, average resolution time, and SLA compliance (≤240 hrs).
AssigneeIdentityWho it's assigned to. Drives per-agent breakdowns and "My Tickets". Logins not in our DB appear under Non-registered logins.
ResolvedByIdentityWho resolved it (an agent, or AutoSIM for automated closures). Drives resolver stats.

Powers the deeper analytics

FieldUsed for
RootCauseThe Incident Type classification and repeat-incident (HI) breakdowns.
RootCauseDetailsDetecting Historical Incident / Cnt > 0 (repeat incidents).
ClosureCodeImmediately Resolved, Automatically Closed — classifies first-time pet incidents.
TitleRegion detection (US/UK/CA/…) for the geographic breakdown.
Export with these columns present and correctly named. If RootCause/RootCauseDetails are missing, the incident-type and repeat-incident sections will be sparse, but core counts (queue, SLA, ages) still work as long as ShortId, CreateDate, Status, and ResolvedDate are present.

5. What information you can see

Live Dashboard (everyone; ticket detail logged-in only)

  • KPI summary — total tickets, in-queue, resolved, AutoSIM, average resolution time, SLA %, and more.
  • Repeat Incident (HI) data — repeat incidents (Cnt > 0), split into pet vs non-pet, with percentages and the pet-vs-non-pet gap.
  • Ticket Age Classification — five color tiles:
    • GREEN 0–96 hrs (0–4 days)
    • YELLOW 96–168 hrs (4–7 days)
    • RED 168–240 hrs (7–10 days)
    • BLACK > 240 hrs (> 10 days)
    • PURPLE Reopened (⚠ shows if a reopened ticket is held by someone outside the allowed reviewers)
    Click any tile (logged in) for the per-agent breakdown, split into Registered users vs Non-registered logins, then drill into an agent's tickets. Download CSVs per segment.
  • SLA Compliance per Week (≤240 hrs) — a wave chart of each week's SLA % for the current quarter, drawn as each week passes.
  • Incident Types — ranked table; click a type (logged in) for the agent breakdown.
  • Historical Incidents (Cnt > 0) — repeat-incident root-cause breakdown; click a row (logged in) for the agent breakdown.
  • Daily and weekly created vs resolved charts.

Other pages (logged-in)

  • Groups — A1 / A2 / B group performance and totals.
  • Previous Week — the prior week's created/resolved report.
  • Shift Report — a copy-ready shift handoff summary (choose region).
  • My Tickets — your own open tickets, deadlines (240h), and per-ticket comments.
  • PHD Tools — Common Blurbs, Hashtags, and Paging contacts (each card has a Copy and a View button). Admins can add/edit/delete blurbs and hashtags.
  • Update data log — full audit history of every upload/publish and what changed.
  • Agent Analytics and Last 24 Hours — Admin+ (Managers excluded from Agent Analytics). Last 24 Hours also shows a Help Activity section.
  • Users — Owner only: create accounts, set roles, reset passwords, remove users.

6. The Help feature — how contractors ask, and how you help

Contractors (editors) can raise questions on their own tickets. Admins, Managers, and the Owner answer them.

How a contractor asks for help

  • On My Tickets, each of their tickets has an Ask for help button.
  • They click it, type their question, and submit.
  • Only one open request per ticket at a time. To ask another question on the same ticket, they must first close the current one with Help received.

How you (Admin / Manager / Owner) help

  1. On the live dashboard, find the Alerts button beside the quarter title. A red badge shows the number of open requests (hidden when none). The button is visible to all logged-in users, but only Admin+ can reply.
  2. Click Alerts. Each open request shows who asked, which ticket (linked), their question, and any replies so far.
  3. Type your reply and click Reply. Replies are append-only and threaded — multiple replies over time, each attributed and timestamped.
  4. The contractor sees your replies inline on their My Tickets page, in that ticket's thread.

Closing the loop

  • When satisfied, the contractor clicks Help received. It drops off the Alerts list but is kept for the record (nothing is deleted).
  • Every question and answer is documented in Last 24 Hours → Help Activity: who asked, the ticket, the question, who replied, and open/resolved status.

7. Quick operational checklist

  • Logged in with my own account.
  • Changed my temporary password (Profile → Security → Change Password).
  • Set my display name / photo.
  • Confirmed my CSV has: ShortId, CreateDate, Status, ResolvedDate, AssigneeIdentity, ResolvedByIdentity (plus RootCause / RootCauseDetails / ClosureCode / Title for full analytics).
  • Uploaded via Upload new data, reviewed the Upload Complete summary.
  • Checked the Alerts badge and answered any open help requests.
  • Reviewed the Update data log if I need to audit a change.

8. FAQ / troubleshooting

A visitor can't see tickets when clicking a tile.

Expected — ticket-level detail is logged-in only. Ask them to log in, or if they need an account, reach out to @harisss (also linked in the "Login required" popup).

An assignee like "vaine" shows under "Non-registered logins".

Their login isn't an account in our user database. It's informational — those tickets still count everywhere; they're just separated in the per-agent drilldown so you can tell registered users apart from unknown/default logins.

My upload was flagged as "cross-quarter".

Your CSV contained tickets from a quarter other than the live one. Review the prompt before confirming so you don't overwrite another quarter's data.

Where do I see who changed what?

Update data log — records each upload/publish with the change summary (added / updated / reopened / auto-closed / unchanged).

For account creation, role changes, or password resets you can't do yourself, contact the Owner — @harisss.
